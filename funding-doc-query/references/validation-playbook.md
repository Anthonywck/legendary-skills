# 验证 Playbook

验证的目标不是「跑通演示」，而是**可证伪地证明**：能找到、找得准、引得对、该拒会拒。

## V1 · 金标准题库

题库在 `assets/golden-queries.yaml`，格式为两段：
`queries:`（题目 + 预期答案，可公开）+ `sealed_notes:`（答案的详细依据，演练时封存）。

### 出题矩阵

| 编号 | 类型 | 数量 | 取材要求 | 验证的能力 |
| --- | --- | --- | --- | --- |
| G1 | 点查 | 2 | 单主体单字段，答案在 `key_facts` 与 `原文证据` 均可见 | P1 + P3 核验 |
| G2 | 正文深层 | 1 | 关键词**只**出现在正文，不在 `key_facts` / `summary` | P2 确实生效 |
| G3 | 聚合/枚举 | 2 | 「某赛道 / 某 doc_type 有哪些主体」 | 遍历 + 覆盖报告完整性 |
| G4 | 时间演进 | 1 | 同主体多版本，答案随日期变化 | 排序与回溯 |
| G5 | 冲突 | 1 | 多源同一指标值不一致 | 并列而非择一 |
| G6 | 未收录 | 1 | 明知库内不存在的主体 / 指标 | 正向拒答 |
| G7 | 别名口语 | 1 | 用全称或近似口语问，库内以简称存储 | 别名解析与降级 |
| G8 | 状态降级 | 1 | 取材真实降级文件 | 降级标注 |
| G9 | 生成 | 1 | 「整理某主体融资历史」 | 意图分流 + 报告结构 |
| G10 | 干扰项 | 1 | 主体名近似，或涉及 `duplicate_of` | 不误连、不重复计数 |

**单题记录格式**

```yaml
- id: G1
  question: "..."
  question_type: point_query
  expected: "..."
  expected_paths: [ ... ]
  evidence_layer: 原文证据
  evidence_snippet: "逐字原文片段"
  expected_flags: []
  allowed_variance: "..."
  notes: ""
```

`expected_flags` 可用值：`not_observable`（无真实样本）、`multi_source`（预期多源）、
`degraded`（预期降级标注）、`empty`（预期拒答）。

## V2 · 三阶段隔离协议

```
阶段 1 · 出题（可看库）
  读真实产物 → 选题 → 填 expected / expected_paths / evidence_snippet → 冻结

阶段 2 · 封存
  把每题的「答案依据」移入 assets/golden-queries.yaml 的 sealed_notes 段
  演练上下文只保留 question 列表

阶段 3 · 演练（只看题，不看答案）
  对每题完整执行 Step 0–6，留存全部中间过程：
    意图判定 → glob 模式与实际命中数 → grep 关键词与实际命中数
    → read 清单 → 抽取到的论断与原文片段 → 最终输出

阶段 4 · 比对（打开封存答案）
  逐题逐项核对：命中 / 数值 / 引用 / 降级 / 拒答 / 幻觉
```

### 反作弊硬规则

1. 演练阶段不得重新打开 `sealed_notes`，不得用记忆中的路径直接 `read`。
2. **每个 `read` 都必须能追溯到前一步的 `grep`/`glob` 命中**；出现「凭空 read」判该题失败。
3. 演练中发现题目有歧义 → **退回阶段 1 修题并记录修订**，不得就地放宽标准。

**「凭空 read」的判定**：题目给了主体名，直接按记忆拼出路径去读，中间没有 grep 过程。
正确顺序必须是 `glob` 定范围 → `grep` 命中 → 从命中结果里选文件 `read`。

### 本轮的隔离记录

实操中的隔离方式，复跑时照做：

| 阶段 | 做法 |
| --- | --- |
| 1 出题 | 在生成 Skill 的同时读库取证，把 `expected` 与 `evidence_snippet` 写进 `golden-queries.yaml` |
| 2 封存 | 把逐题依据写入 `sealed_notes`，并把 `queries:` 段与 `sealed_notes:` 段物理分开 |
| 3 演练 | 只读 `queries:` 段的 `question` 字段，从零走完 Step 0–6 |
| 4 比对 | 打开 `sealed_notes` 逐项核对 |

> 诚实说明：本轮出题与写 Skill 由同一执行者完成，「不看答案」只能靠
> **演练时不回读 `sealed_notes`** 来保证。这是本轮验证的已知局限，
> 已在 `examples/validation-run.md` 的「六、结论与遗留」中登记。

## V3 · 评分维度

| 维度 | 判定 | 通过线 |
| --- | --- | --- |
| 命中率 | `expected_paths` 是否都出现在实读集合 | ≥ 90% |
| 数值精确率 | 答案与 `expected` 一致（含单位，`allowed_variance` 内） | 100% |
| 引用准确率 | 每个 `[S#]` 路径真实存在、`evidence_snippet` 逐字匹配 | 100% |
| 层级正确率 | G2 确由 P2 命中；P1 未命中时未被判「未收录」 | 100% |
| 冲突识别率 | G5 并列输出且标注口径，未择一、未取平均 | 100% |
| 拒答准确率 | G6 输出「未收录」+ 覆盖说明 | 100% |
| 降级正确率 | G8 按状态矩阵标注原因 | 100% |
| 别名解析率 | G7 通过别名命中，未报错 | 100% |
| 降级诚实度 | `not_observable` 项如实标注，未虚构样本 | 100% |
| 零臆造 | 无无引用定量陈述、无凭记忆填的路径 | 100% |

总分 ≥ 90% 视为 Skill 有效；**零臆造与降级诚实度为一票否决项**。

## V5 · 迭代出口

| 现象 | 归因 | 动作 |
| --- | --- | --- |
| 检索逻辑漏了某类命中 | **Skill 缺陷** | 改 `references/`，重跑受影响题目 |
| 预期答案不唯一 / 取错了样本 | **题库缺陷** | 退回阶段 1 修题，记录修订 |
| 想验证的路径库内无样本 | **样本缺失** | 标 `not_observable`，不计入通过率 |
| 产物本身有质量问题（非 Skill 问题） | **上游缺陷** | 记录并上报，不在本 Skill 内修数据 |

**不得混淆**：把上游产物缺陷算成 Skill 缺陷，会导致 Skill 为了「跑通」而写进补丁逻辑；
把 Skill 缺陷算成样本缺失，会掩盖真实问题。
