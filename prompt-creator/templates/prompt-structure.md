# Prompt 生成结构（9 元素）与裁剪规则

生成的 Prompt 遵循固定顺序，但**不是每个元素都必需**。按场景裁剪，避免信息过载。

## 元素总览

| # | 元素 | 作用 | 默认 |
|---|------|------|------|
| 1 | 角色 | 设定专业身份与视角 | 必含（可极简） |
| 2 | 任务 | 一句话说清要做什么 | 必含 |
| 3 | 背景 | 补充受众 / 目的 / 上下文 | 按需 |
| 4 | 输入 | 声明输入材料与 `{{变量}}` | 有输入时 |
| 5 | 要求 | 约束 / 规则 / 禁止项 | 必含 |
| 6 | 输出格式 | 结果的形态（结构 / 字段 / 格式） | 结构化任务必含 |
| 7 | 示例 | few-shot，锁定精度与格式 | 精度敏感时 |
| 8 | 步骤 | 多步任务的执行顺序 | 复杂任务时 |
| 9 | 自检 | 让模型输出前自我核查 | 可验证任务时 |

## 裁剪规则

**骨架（几乎总是保留）：** 角色 + 任务 + 要求 + 输出格式

**按需加入：**

- **背景** —— 仅当模型缺了它就会答偏（如「给部门经理看」这类受众信息改变了内容取舍）。简单自明任务可省。
- **输入** —— 仅当存在输入材料或变量（会议纪要、原文、`{{变量}}`）。从零生成的任务可省。
- **示例** —— 仅当输出格式非自明、或对措辞 / 结构要求高。会过度约束或任务已清晰时省。
- **步骤** —— 仅当任务多步、需按序执行。单次生成的任务可省。
- **自检** —— 仅当任务有「对错」可验（事实、格式、清单类）。开放性创作任务可省。

## 决策要点

- 问自己：**删掉这个元素，输出会变差吗？** 不会 → 删。
- 每个元素只写最少必要内容；一句话能说清就不写一段。
- 变量一律 `{{双花括号}}` 标注，方便复用替换。

## 各元素写法要点

- **角色**：一句话「你是擅长 X 的 Y」。别堆砌头衔。
- **任务**：动词开头，明确对象与产出。
- **背景**：只写影响输出的那一条（受众 / 目的 / 边界）。
- **输入**：列出材料与变量，变量用 `{{}}`。
- **要求**：编号列出，每条一句话，含禁止项（如「不编造」）。
- **输出格式**：给具体结构（表格列 / JSON 字段 / 段落数），越具体越稳。
- **示例**：给 1 个完整示例即可，别给 5 个稀释质量。
- **步骤**：编号，每步一个动作。
- **自检**：列 2-4 条模型能自判的检查项。
