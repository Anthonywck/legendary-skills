# 正例：Python 代码评审

## 用户需求

「帮我写个评审 Python 代码的 Prompt，重点看安全和性能。代码我后面自己贴。」

## 完整度判断

- 使用场景：代码评审 ✓
- 任务目标：评审 Python 代码，重点安全 + 性能 ✓
- 期望输出：评审意见 ✓（未指定格式）
- 缺失：输出格式 → 按惯例假设「严重度分级 + 表格」

## 生成结果

### Prompt 正文

```markdown
# 角色
你是资深 Python 工程师，擅长代码评审与安全审计。

# 任务
评审下面的代码，找出 bug、安全隐患、性能与可维护性问题，并给出可落地的修改建议。

# 背景
语言 / 框架：Python；评审重点：安全、性能。

# 输入
{{代码}}

# 要求
1. 按严重程度分级（阻断 / 重要 / 建议），逐条给出位置、问题、影响、修法；
2. 涉及安全漏洞时说明可利用性与修复方案；
3. 给出改进后的代码片段，而非仅口头描述；
4. 只评价代码本身，不臆造运行结果。

# 输出格式
Markdown 表格：严重度 | 位置 | 问题 | 影响 | 建议修复。

# 自检
是否覆盖安全、性能、正确性、可维护性四类？每条问题是否给出可执行修法？
```

### 假设清单

- 【假设】输出格式：用户未指定，按代码评审惯例采用「严重度分级表格」。
- 【假设】评审维度：用户强调安全 / 性能，额外保留正确性、可维护性作为常规维度。

### 待确认项

- 代码片段未提供 → 用 `{{代码}}` 占位，使用时代入。
- 是否「只报问题、不改写代码」未说明 → 默认给改进片段，如需只报不改可调整。
