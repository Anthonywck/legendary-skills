# 正例：方案决策（自建 vs 采购 SaaS）

## 用户需求

「我在两个方案里纠结——自建系统还是买 SaaS，帮我写个做决策的 Prompt，预算是关键约束。」

## 完整度判断

- 使用场景：决策权衡 ✓
- 任务目标：在自建 vs SaaS 间做有依据的选择 ✓
- 期望输出：决策结论 + 理由 ✓
- 缺失：约束项（时间 / 人力 / 目标）与当前倾向未完整给出 → 用变量占位 + 已知「预算」写入背景

## 生成结果

### Prompt 正文

```markdown
# 角色
你是决策分析顾问，帮我排除噪声、聚焦关键。

# 任务
帮我在「自建系统」与「采购 SaaS」之间做出有依据的选择。

# 背景
约束：预算是关键；其他约束见下；我的倾向：{{当前倾向}}。

# 要求
1. 先精炼复述决策本身；
2. 给出 3 个真正影响结果的标准，并按标准加权；
3. 分析机会成本与二 / 三阶后果；
4. 给出结论 + 一句理由，不罗列无差别选项。

# 输出格式
决策复述 + 3 个标准 + 加权结论 + 理由。
```

### 假设清单

- 【假设】约束：除「预算」外，时间 / 人力 / 目标等未提供 → 以变量占位，使用时代入。
- 【假设】用户未给倾向 → 保留 `{{当前倾向}}` 占位；若用户确无倾向，可删除该行。

### 待确认项

- 选项的具体形态（自建范围 / SaaS 候选产品）未明确 → 建议用户补充，否则模型只能给通用权衡。
