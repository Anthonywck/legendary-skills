# 正例：行业研究报告 PDF 全流程

样本：`datas/行业报告/半导体检测行业报告：集成电路国产化加速，第三方检测发展空间广阔-230722（28页）.pdf`

## 1. 命名结构与 BP 的差异

行业报告的文件名形态与 BP 完全不同：

| 特征 | BP | 行业报告 |
| --- | --- | --- |
| 前缀 | `【赛道】` | 通常无；有 `机构：` |
| 日期 | 多数缺失 | 55/84 份带 `-YYMMDD` |
| 页码 | 无 | 普遍带 `（N页）` |
| 主体 | 企业 | 发布机构 |

因此主体判定走不同分支（见 `taxonomy.md`）。

## 2. 字段推导

| 字段 | 值 | 依据 |
| --- | --- | --- |
| `doc_type` | `REPORT` | `source_root=行业报告`，名不含「白皮书/手册」 |
| `topic` | `半导体` | 无方括号，`keyword_rules` 首条命中「半导体」 |
| `subject` | `半导体检测行业报告` | 冒号前无机构名，退回「取第一段」 |
| `date` | `2023-07-22` | 文件名 `-230722`，先剥离 `（28页）` 防止页码误判 |
| `date_source` | `filename` | |
| `key_facts` | 分析师、发布机构、页数 | 正文/首页可抽到 |

**`（28页）` 必须先剥离**：若先跑 `YYMMDD` 正则，`28页` 前后的数字
可能被凑成伪日期。剥离页码是行业报告的必需步骤。

**发布机构的两种来源**：
- 文件名带 `机构：` 时直接取（如 `赛迪译丛：…`、`云岫资本：…`）
- 否则从正文取（分析师签名旁的组织名）

本例正文首页有 `证券研究报告 / 2023年07月22日` 与分析师签名，
因此 `key_facts` 能补出 `分析师: 姚健`、`发布机构: 国海证券`。

## 5. 只有年份、没有月日的 29 份报告

数据里有 29 份报告文件名只有 `（2023）` 或 `2023`，例如：

```
德勤&GSA：2024亚太地区半导体行业展望报告（11页）.pdf
西门子：2023电子与半导体行业白皮书（62页）.pdf
```

处理：

- 年份从文件名取 → `date: 2024`，`date_source: filename`
- 若文件名也无线索，才落到 `doc_meta`（PDF creationDate）或 `fs_mtime`
- **绝不**因为「别的报告都有月日」就补齐成 `2024-01-01`

`date` 允许 `YYYY` 精度，正是为这类情况设计的。检索按目录年份
`by_topic/半导体/2024/REPORT/` 就能定位，不需要月日。

## 6. 白皮书的分支

```bash
datas/行业报告/Acloudear：2024半导体IC行业数字化转型白皮书（43页）.pdf
```

名含「白皮书」→ `doc_type: WHITEPAPER` → 落 `by_topic/半导体/2024/WHITEPAPER/`。

这样检索时可以按 `**/WHITEPAPER/*.md` 一次性列出所有白皮书。

## 7. 忽略项

`datas/行业报告.zip`（1.1 GB）：已解压，其内容就是上面两个文件夹。
本 Skill 在 `formats.yaml` 中把 `.zip` 显式登记为 `ignored`——
既不展开也不引用，且这条信息写进了配置表，任何人看到都知道是**有意忽略**而非漏掉。
