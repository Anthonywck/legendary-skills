# 元数据 Schema

权威基线是《搭建方案》3.3 的字段表。本 Skill 只做了**两处扩展**，其余语义不变。

## 字段总表

| 字段 | 必填 | 来源 | 说明 |
| --- | --- | --- | --- |
| `title` | 是 | 文件名 | 去扩展名、清洗非法字符 |
| `doc_type` | 是 | 规则 | `BP` / `REPORT` / `WHITEPAPER` / `DOC` / `NOTE` / `OTHER` |
| `project` | 是 | — | **恒为 `null`**：数据无项目概念，见偏离说明 |
| `date` | 是 | 五级优先级 | `YYYY-MM-DD` / `YYYY-MM` / `YYYY` / `unknown` |
| `date_source` | 是 | **扩展字段** | `doc_text` / `filename` / `doc_meta` / `fs_mtime` / `unknown` |
| `version` | 否 | 文件名 | 默认 `v1.0` |
| `status` | 否 | 文件名 | `draft` / `review` / `final` |
| `round` | 否 | 文件名→正文 | 融资轮次，如 `D轮`、`Pre-A+轮` |
| `author` | 否 | 文档元数据 | PDF/PPTX 的 author 属性 |
| `reviewers` | 否 | — | 恒为 `[]`，格式与 3.3 一致但数据中不存在 |
| `subject` | 是 | **扩展字段** | 企业主体简称；报告为发布机构 |
| `topic` | 是 | 赛道词表 | 一级赛道，封闭集 |
| `tags` | 是 | 赛道 + 主体 + 别名 | 中文原词，供口语化命中 |
| `summary` | 是 | 规则生成 | 1–3 句，全部为原文摘录 |
| `key_facts` | 是 | 规则抽取 | 每条 `字段: 值` 独立一行 |
| `related_docs` | 否 | dedupe | 同主体其它产物的相对路径（与 `md_path` 同基准，不以 `datas/` 开头） |
| `duplicate_of` | 否 | dedupe | 疑似重复时指向主**产物**的相对路径（与 `md_path` 同基准）。索引 CSV 里仍存 `source_path`，两者各司其职 |
| `source_available` | 是 | 同步 | 源文件是否仍存在 |
| `source_root` | 是 | 扫描 | `商业计划书` / `行业报告` |
| `source_path` | 是 | 扫描 | 相对项目根的原始路径 |

**为什么扩展 `subject`**：「主体三处可 grep」是硬约束，且 `project` 已无意义。
把主体放进 `project` 会篡改 3.3 的字段语义，因此新增字段并在偏离说明登记。

**为什么扩展 `date_source`**：日期有五种可能来源，若不留痕，
就无法判断一个 `2026-07-28` 是真实落款还是文件系统拷贝时间。这是防臆造的核心。

## 字段取值矩阵（按 doc_type）

| 字段 | BP | REPORT | WHITEPAPER | DOC / NOTE | 缺失时 |
| --- | --- | --- | --- | --- | --- |
| `subject` | 企业简称 | 发布机构 | 发布机构 | 文档主题词 | `unknown` |
| `round` | 常出现 | 不适用 | 不适用 | 不适用 | `null` |
| `alias_full` | 工商全称（若可确认） | 通常无 | 通常无 | 通常无 | `null` |
| `key_facts` 含「页数」 | 是 | 是 | 是 | 是 | — |
| `key_facts` 含「分析师/发布机构」 | 否 | 是（若抽到） | 否 | 否 | — |
| `key_facts` 允许为空 | 否 | 否 | 否 | **是** | — |

`DOC` / `NOTE` 是技术文档与笔记本，本来就没有融资数据。
强行要求 `key_facts` 非空只会逼出臆造；校验器对这两类放行。

## 别名四件套

`tags` 与「元数据速查」区必须覆盖四种写法，使用户用任一形式 grep 均可命中：

| 字段 | 含义 | 来源 | 缺失时 |
| --- | --- | --- | --- |
| `alias_full` | 工商全称 | 正文中**包含主体名**的 `…有限公司/股份有限公司` | `null` |
| `alias_short` | 简称 | `subject` | — |
| `alias_en` | 英文名 | 主体名中的拉丁字母串 | `null` |
| `alias_pinyin` | 拼音首字母 | `pypinyin` | `null`（未装该包） |

**`alias_full` 必须包含主体名**。正文里第一个出现的全称常常是无关公司：
某 BP 正文先提到「中国航天科技集团有限公司」，直接取首条会把巨头记成该主体全称。
同理，折行文本会从句子中间截出「梭科技股份有限公司」这种残缺全称——
因此正则的左边界必须是「非公司名字符」，且左首不能是「的是为由在和及称」。

## key_facts 规范

每条一行，统一 `字段: 值`，冒号后一个空格。只收**有原文证据**的字段。

允许的字段：

`轮次` `投前估值` `投后估值` `融资金额` `成立时间` `所在地区` `营收` `分析师` `发布机构` `页数`

**`成立时间` 的主语约束**：「成立于 2002 年」在 BP 里通常说的是行业标杆公司，
不是本主体。因此只接受主语为「公司 / 本公司 / 我们」的句式。

## 摘要规范

`summary` 由三部分组成，全部来自原文，不生成新句子：

```
① 首句 = 文档标题（文件名主干）
② 「{主体}的{文档类型}，归属「{赛道}」赛道。」
③ 有融资数据时：「原文关键数据：轮次 D轮；投后估值 10.2亿元。」
   无融资数据且为报告时：「报告主线：{原文首段摘录}」
   否则：「原文未提供明确的融资数据。」
```

句式固定，是为了让「某公司在哪个赛道」「有没有拿到融资」这类问题
可以只 grep 摘要区就得到答案，而不必展开正文。

## 抽取失败时的取值

| extraction_status | summary 处理 | key_facts | 正文 |
| --- | --- | --- | --- |
| `ok` | 正常生成 | 规则抽取 | 完整 |
| `needs_ocr` | 固定警示语 | 仅「页数」 | 空 |
| `encoding_error` | 固定警示语 | 仅「页数」 | 空 |
| `corrupt` / `empty` | 固定警示语 | 仅「页数」 | 空 |
| `too_large` / `unsupported` | 固定警示语 | 仅「页数」 | 空 |

失败态下**绝不**把不可信正文喂给抽取器——乱码里同样能匹配到「估值」「亿元」等字样，
放行就会产出通篇臆造。

## 可 grep 性要求

1. 字段名固定，不改大小写、不加前缀
2. `key_facts` 每条独立一行，便于 `grep -A`
3. `tags` 用中文原词（`第三代半导体` 而非 `third-gen-semiconductor`）
4. 「元数据速查」区逐行列出主体别名，使 `grep "公司全称"` 直接可命中
