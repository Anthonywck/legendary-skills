# 命名与日期

## 文件名规范

```
{YYYY-MM-DD}_{文档类型}_{主体}_{版本号}[_{状态}].md
```

与《搭建方案》3.2 相比只动了两处，都在偏离说明里登记：

| 改动 | 原规范 | 本规范 | 原因 |
| --- | --- | --- | --- |
| 追加主体段 | `{日期}_{类型}_{版本}` | `{日期}_{类型}_{主体}_{版本}` | 数据无项目维度，主体是唯一稳定的业务标识；也是「主体三处可 grep」的第一处 |
| 日期精度放宽 | 固定 `YYYY-MM-DD` | 允许 `YYYY-MM` / `YYYY` | 多数 BP 只有「2022年5月」这类月级落款，补 `-01` 属于臆造 |

日期段只接受 `\d{4}-\d{2}-\d{2}`、`\d{4}-\d{2}`、`\d{4}`、`unknown` 四种形态。

示例：

```
2022-05-15_BP_森国科碳化硅SiC_v1.0.md
2023-07-22_REPORT_半导体检测行业报告_v1.0.md
2023-02_BP_晶栅科技_v1.0.md
unknown_REPORT_沙利文_v1.0.md
```

## 日期来源优先级

**顺序不可交换**，且每一级都有防臆造闸门。

### ① 正文落款（`date_source: doc_text`）

搜索范围严格限定在两处：

- 封面区：正文前 6 个非空行
- 落款区：正文最后 12 个非空行

**不搜索正文中段。** 这是最关键的一条——真实数据里
「2017年5月26日，Veeco 完成收购 SMEE…」就出现在页尾附近，
若按「末两页全文搜索」会把这条历史事件日期当成文档日期。

判据（`common.date_line_of`）：该行必须**以日期为主体**

```
接受: 2022年5月            （长度 ≤24 且去掉数字/年月日后剩余文字 ≤6 字）
接受: 2022-02-20
拒绝: 2022年5月，公司完成A轮融资   （剩余叙述文字过多）
```

封面区只认「日 / 月」精度，不认单独年份——封面常印「2023」作为品牌年份而非文档日期。

### ② 文件名（`date_source: filename`）

依次尝试：

| 形态 | 例 | 说明 |
| --- | --- | --- |
| `YYYYMMDD` | `…20220427项目商业计划书.pdf` | 优先 |
| `YYMMDD` | `…-230722（28页）.pdf` | 先剥离「（N页）」再匹配 |
| `YYYY年M月` | `…2022年5月…` | 月级 |
| `(YYYY)` | `…（2023）…` | 年级 |

**必须先剥离页码**：`（15页）`、`（125页）` 里的数字会被 `YYMMDD` 正则误吃。
剥离后仍要求月份 1–12、日在 1–31 且年份在 2010–当前年+1。

### ③ 文档内部元数据（`date_source: doc_meta`）

PDF `creationDate` / `modDate`，PPTX/DOCX `core_properties.created`。
**只取 `creationDate`，不取 `modDate`**——modDate 常被二次编辑刷成同步日期。

### ④ 文件系统 mtime（`date_source: fs_mtime`）

前三级全无时兜底。mtime 通常是拷贝时间（本批数据全是 `2026-07-28`），
会明显偏离真实年份，因此每当触发该级，产物摘要里不会把它当作业务事实。

### ⑤ 未知（`date_source: unknown`）

`date: unknown`，落 `by_topic/{topic}/unknown/{doc_type}/`。

## 日期归一化陷阱

中文 PDF 常用 **CJK 部首字形**代替常用字：`⽉`(U+2F49) 而非 `月`(U+6708)、
`⽇` 而非 `日`。直接用 `[年月日]` 匹配会漏。因此所有日期正则先过
`unicodedata.normalize("NFKC", ...)`，把部首字形折回标准汉字。

## 版本号与状态

| 来源 | 判定 |
| --- | --- |
| 文件名含 `v2.3` / `v2` | `v2.3` / `v2.0` |
| 无版本信号 | 默认 `v1.0` |
| 文件名含「简版」「精简版」「摘要版」 | `status: draft` |
| 含「终版」「定稿」「final」 | `status: final` |
| 含「修订」「复审」「review」 | `status: review` |

## 主体名清洗

落盘前统一处理，保证 macOS / Windows / Linux 都能创建同名文件：

1. NFKC 归一化
2. 移除 `\ / : * ? " < > |` 与控制字符
3. 空白全部去掉
4. 截断到 20 字（BP 主体）/ 20 字（报告机构）
5. 去首尾 `.` `-` `_`
6. 空值 → `unknown`

## 同名冲突

主体、日期、类型、版本全部相同时，路径会撞车。处理：

1. 若撞车的是**同一个源文件**（重复处理）→ 复用原路径（幂等）
2. 若是**不同源文件** → 追加正文哈希前缀消歧：
   `…_v1.0-38b3db91.md`（依次尝试 8 / 12 / 16 位）

绝不做「覆盖」或「静默跳过」。

## 异常值处理

| 情况 | 处理 |
| --- | --- |
| 日期超出 1990–当前年+1 | 视为无效，降级到下一优先级 |
| 文件名只有 6 位数字但月份/日非法（如 `-239999`） | 不采信，降级 |
| 主体为空或只剩标点 | `unknown` |
| 赛道落到「其他」 | 必须写 `topic_reason`，进入人工复核清单 |
