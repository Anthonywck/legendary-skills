# 单文件抽取 SOP

处理一份文件的完整链路。`sync.py` 内部按此顺序执行，人工排障时也照此逐段核对。

```
① 探测格式 → ② 解析正文 → ③ 判定质量 → ④ 抽取元数据
→ ⑤ 校验字段 → ⑥ 推导落位 → ⑦ 写入产物 → ⑧ 登记索引
→ ⑨ 源文档疑点（只提示、不修改）
```

任何一步失败只记 `_index/errors.log` 并继续下一份，**不中断批次**。

## ① 探测格式

查 `assets/formats.yaml`：

| 扩展名 | 解析器 | 说明 |
| --- | --- | --- |
| `.pdf` | pymupdf | 文本层按页拼装；无文本层的页可 OCR |
| `.pptx` | python-pptx | 逐页文本框 + 表格 + 备注 |
| `.docx` | python-docx | 段落（识别层级）+ 表格 |
| `.ppt` / `.doc` | legacy-office | 纯 Python（olefile）；失败时给 `soffice` 命令 |
| `.png` `.jpg` `.bmp` `.tif` `.webp` 等 | image-ocr | 直接 OCR |
| `.md` / `.markdown` | markdown | 原样保留，不重新渲染 |
| `.txt` / `.log` | plain-text | 依次尝试 utf-8-sig / utf-8 / gb18030 |
| `.csv` / `.tsv` | csv | 自动识别分隔符，转 Markdown 表格 |
| `.xlsx` | xlsx | 逐工作表转 Markdown 表格 |
| `.zip` `.rar` `.7z` | ignored | 不展开、不处理 |
| 其它 | unsupported | 按 `default` 登记，**不静默跳过** |

未登记格式也要在索引里留一行（`md_status=degraded:unsupported`），
以便统计「还有多少文件没被覆盖」。

先做两项前置检查：

- 文件大小为 0 → `corrupt`，不尝试解析
- 超过 512 MB → `too_large`，不尝试解析

解析器一律**把文件读进内存再解析**（`BytesIO`），不持有源文件句柄。
否则 Windows 上会阻碍用户对原件改名/移动，违反「原件只读、可被外部自由操作」。

## ② 解析正文

### PDF

逐页 `page.get_text()`，按页拼成 `### 第 N 页` 的 Markdown。

无文本层的页在**阶段二**（`run_ocr.py`）单独补 OCR；阶段一只标记 `needs_ocr`。

不用 `pymupdf4llm` 作为默认路径：2.0 起它会**默认调用 RapidOCR**，
单份 19 页 BP 从 5 秒劣化到数分钟，且参数藏在 `**kwargs` 里无法稳定关闭。
需要更强的标题/表格结构时显式开启：

```bash
FDS_LLM_MARKDOWN=1 python extract.py <file>
```

### PPTX

逐页取 `shape.text_frame.text` 与表格行（` | ` 分隔），并追加 `[备注]`。
每页首行作为 `## 第 N 页：{首行}` 标题。

### DOCX

按样式名区分 `Heading*` 与正文；表格单独成块。

## ③ 判定质量

`extraction_status` 是后续所有元数据抽取的闸门。

| 状态 | 判据 |
| --- | --- |
| `corrupt` | 大小 == 0，或解析抛非预期异常 |
| `encrypted` | `doc.needs_pass`，或异常信息含 password/encrypt |
| `too_large` | > 512 MB |
| `unsupported` | 格式未登记或解析器缺失 |
| `needs_ocr` | 有图像但**有文本层的页占比 < 30%**（OCR 关闭或未取得内容时） |
| `encoding_error` | 异域脚本字符占比 ≥ 15% |
| `empty` | 无文本层且无图像 |
| `ok` | 其余；表格类以「有数据行」为准，不套用正文 50 字阈值 |

**`needs_ocr` 必须按页覆盖率判，不能按总字数判。**
真实案例：一份 26 页扫描件，前 25 页 0 字符，末页有一段 383 字的推广水印，
按「总字数 > 0」会被误判为可解析，实际上 96% 的内容永远检索不到。

**`encoding_error` 的判据**是「异域脚本字符占比」，而不是「中文占比低」——
外文文档本身就不该被当成乱码。

## ④ 抽取元数据

只在 `status == ok` 时进行（`build_frontmatter.usable_text`）。

抽取值 → 一律带**原文证据片段**，写入产物的「原文证据」表（三列：字段 / 值 / 原文片段）。
片段只取匹配所在的**同一句**，不跨句拼接——跨句的片段读起来像乱码，也无法自证。
没有证据就不写值，宁可为 `null`。

## ⑤ 校验字段

`validate_fields()` 检查：

- 必填字段齐备
- `date_source` 在枚举内；`date=unknown` 与 `date_source=unknown` 必须同进同退
- `topic` 在封闭集内
- `doc_type` 在枚举内
- `key_facts` 非空且每条符合 `字段: 值`
- `subject` 出现在 `tags` 中

校验失败不阻断写盘，而是把问题追加进产物的「抽取提示」区，
让问题可见、可批量复查，而不是让整批任务停在某一个文件上。

## ⑥ 推导落位

见 `taxonomy.md`。要点：

- 路径由字段**唯一推导**，不含随机量
- 撞车时若同源 → 复用（幂等）；异源 → 追加哈希前缀
- 路径变更（改名/日期变化）时**移动**旧产物，不复制

## ⑦ 写入产物

固定结构，保证逐字节幂等：

```markdown
---（frontmatter，字段序固定）---
# 标题
<!-- dedupe:begin --> … <!-- dedupe:end -->   ← 固定锚点，供 dedupe 阶段替换
## 元数据速查
## 摘要
## 关键事实
## 原文证据
## 抽取提示（仅有告警时）
## 正文
```

写入前先比对现有内容，相同则跳过（避免刷新 mtime）。

## ⑧ 登记索引

一行一源文件，字段见 `sync-and-index.md`。

## ⑨ 源文档疑点：只提示，不修改

**本 Skill 是「结构的转写者」，不是「内容的编辑者」。** 产物的职责是让原件更容易被检索，
不是替原件做校正。因此这一步的产出**只有提示与建议**。

### 适用对象

原件（PDF / PPTX / DOCX / 图片 OCR / 表格）里出现的**内容疑点**，分三类：

| 类型 | 例子 |
| --- | --- |
| 逻辑错误 | 同一指标前后矛盾；金额与比例算不平；融资轮次倒序；日期晚于文件落款 |
| 常识错误 | 明显不合理的数据量级；单位错配（万元/亿元）；公司名与地域产业链不符 |
| 专业错误 | 术语误用；财务口径错误（投前/投后混用）；行业规则错误（如估值口径、国资审批流程） |

抽取失败（乱码、扫描件、加密）不属于这一类，见 ③ 的质量判定。

### 判定顺序（缺一步都不算数）

1. **定位原文**：必须能引到原句与位置（页码 / 幻灯片号 / 工作表）。引不到的不提。
2. **交叉验证**：至少两条独立依据，**不能只凭一次推理就下结论**——
   - 文档内部：同一文件的其他章节、表格、脚注、附录是否给出不同数值
   - 文档之间：同主体的其它文档、同赛道的其它报告是否一致（`grep` 现有 `datas-md/`）
   - 外部事实：单位换算、会计恒等式、公开可查的机构名/人名/地名、行业通行口径
3. **确认错误真实存在**：若验证后仍无法排除「原文如此、只是我没看懂」，
   **不得报告为错误**。宁可漏报，不可误报——误报会让用户对整套索引失去信任。

### 报告给用户的格式

每条疑点必须带齐四项，缺任何一项都不要报：

```
【疑点】<一句话描述哪里不对>
【原文】"<原句>"（<页码/页签>）
【依据】<交叉验证用的另一处原文 / 算术验算 / 公开事实>
【建议】<建议改成什么，以及为什么>（仅供参考，未写入任何文件）
```

汇总后一次性交给用户，不要逐条打断。用户可以逐条回复采纳 / 不采纳。

### 硬性禁止

- **不得修改原件**（`datas/` 只读，见 ①）。
- **不得把更正值写进产物**：`subject` / `date` / `key_facts` / `summary` / `tags` / 文件名 / 目录名，
  一律按原文如实抽取。发现原件写「投后估值 10.2 亿」但疑似应为「投前」，
  产物里仍然照写「投后估值: 10.2亿元」，把疑点放进报告，**不替它改口径**。
- **不得自行重命名、移动、删除、覆盖任何文件**——包括"顺手"改掉看起来写错的文件名。
- **不得因为疑点而阻断产出**：该文件照常生成 `.md`，疑点单独报告。

### 与「防臆造」的区别

| | 防臆造（③④） | 本步 |
| --- | --- | --- |
| 问题出在 | 抽取不到，想补 | 原文写错，想改 |
| 正确做法 | 写 `null` / `unknown` | 照原文写，另出报告 |
| 共同点 | **都不允许产出原文里没有的东西** | 同左 |

一句话：**原件错了，产物跟着错，但你要说出来**。

## 幂等要求

同一份源文件、同一个配置，两次处理必须产出**逐字节一致**的文件：

| 易破坏幂等的点 | 对策 |
| --- | --- |
| frontmatter 字段顺序 | 固定 `FM_ORDER` 列表 |
| 日期取「今天」 | 日期只来自文档，不来自运行时刻 |
| 列表顺序不稳定 | tags / related_docs 排序后写入 |
| `last_run` 写入产物 | `last_run` 只进索引，不进产物 |
| dedupe 块位置漂移 | 用固定 HTML 注释锚点替换，不猜插入点 |

验证：

```bash
python sync.py --rebuild && find datas-md -type f | sort | xargs sha1sum > a.txt
python sync.py --rebuild && find datas-md -type f | sort | xargs sha1sum > b.txt
diff a.txt b.txt
```
