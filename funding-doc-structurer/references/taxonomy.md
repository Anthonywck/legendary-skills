# 赛道、文档类型与路径推导

《搭建方案》3.1 以 `projects/` 为首要维度，但**实际数据里没有项目概念**：
`datas/商业计划书/` 按企业主体组织，`datas/行业报告/` 按赛道组织。
因此本 Skill 改为「文档类型 → 赛道 → 年份 → 落位」的推导链，维度以赛道优先。

## 路径模板

```
by_topic/{赛道}/{年份}/{doc_type}/{日期}_{DOC_TYPE}_{主体}_{版本}[_{状态}].md
```

| 段 | 取值 | 约束 |
| --- | --- | --- |
| 赛道 | 一级赛道的**中文名** | 封闭集，见下 |
| 年份 | `YYYY` 或 `unknown` | 由 `date` 取前 4 位 |
| doc_type | `BP` / `REPORT` / `WHITEPAPER` / `DOC` / `NOTE` / `SHEET` / `OTHER` | 同时作为目录名与文件名段 |
| 日期 | `YYYY-MM-DD` / `YYYY-MM` / `YYYY` | 原件的真实精度，不补齐 |
| 主体 | 企业简称（报告为发布机构） | 已清洗非法字符，≤20 字 |
| 版本 | `vX.Y` | 无版本信号时取默认 `v1.0` |
| 状态 | `draft` / `review` / `final` | 可选 |

目录深度恒为 4（`by_topic` 不计入），避免 glob 变慢。

## 一级赛道（封闭集）

| 赛道 | 覆盖范围 |
| --- | --- |
| 半导体 | 芯片设计、制造、封测、设备、零部件、材料、功率器件、EDA、产业服务 |
| 新材料 | 非半导体口径的功能/结构材料、制热导热材料、陶瓷基板 |
| 新能源 | 锂电、光伏、储能、BMS、新能源车零部件 |
| 企业服务 | 不以实体产业为主业的软件、咨询、供应链服务 |
| 节能环保 | 水、气、节能、资源回收 |
| 其他 | 显式兜底，必须写 `topic_reason` 供复核 |

新增一级赛道须改 `assets/taxonomy.yaml` 并同步本表，不可临场扩展。

## 赛道判定决策树

```
① 文件名有【X】且 X 在 bracket_map 中？
   → 定案（tags 追加 X 本身，供口语化命中）
② 文件名/首页标题命中 keyword_rules 的第一条？
   → 定案（规则顺序即优先级，不可乱序）
③ 有【X】但未登记 → topic=其他，tags=[X]，登记 topic_reason
④ 无任何信号 → topic=其他，登记 topic_reason
```

**为什么方括号原词降为 tag**：真实方括号粒度极不一致——
`【半导体】`(13)、`【新材料】`(4)、`【芯片制造】`(4)、
以及 `【芯片抛光】`、`【第三代半导体】`、`【GaN基半导体】` 各 1 份。
若直接用方括号做目录，会出现十几个只有一份文件的目录。因此：

- 一级赛道 = 业务实质（封闭、稳定），决定落位
- 方括号原词 = 细分标签（自由、信息量大），进 `tags` 供检索

## doc_type 判定

规则表按顺序匹配，第一条命中即停（见 `assets/taxonomy.yaml` 的 `doc_type_rules`）：

```
① 名称含「白皮书 / 手册 / whitepaper」      → WHITEPAPER
② source_root 含「商业计划书」              → BP
③ source_root 含「行业报告 / 报告」         → REPORT
④ 名称自述「商业计划书 / 融资计划书 / BP」  → BP
⑤ 扩展名 .csv / .tsv / .xlsx                → SHEET
⑥ 扩展名 .md / .markdown                    → NOTE
⑦ 名称含「方案 / 说明 / 教程 / 指南 / 接入 / 安装 / 部署」→ DOC
⑧ 全不命中                                  → OTHER
```

两点设计取舍：

- **白皮书优先于目录名**：白皮书常放在「行业报告」目录下，但检索时
  `glob("**/WHITEPAPER/*.md")` 一次性列出所有白皮书更有价值
- **新增 DOC 而不并入 OTHER**：「方案/说明/教程」在真实数据里很常见
  （本次新增的 AICC 目录 4 份全部落在 DOC/NOTE），
  混进 OTHER 会让「需人工复核」的清单失真

行业报告不细分「券商研报 / 咨询报告 / 译丛」——下游检索不需要这层区分，
多一层只会让 glob 路径更长。

## 主体判定（BP 与报告不同）

| 文档类型 | 主体来源 | 示例 |
| --- | --- | --- |
| BP | 文件名去掉【】前缀与「…项目商业计划书」后缀后的第一段 | `【半导体】森国科SiC -碳化硅项目商业计划书.pdf` → `森国科SiC` |
| REPORT | 文件名冒号前的发布机构 | `赛迪译丛：确保半导体供应链安全…` → `赛迪译丛` |

第一条分隔符是**任意空白或标点**（空格 / `-` / `—` / `：` / `_` / `/`）。
把「任意空格」也算分界是必须的：数据里同时存在
「深圳烯钻科技 半导体…」（空格分隔）与「鹏城半导体 -高端…」（空格加连字符）两种写法。

## 两条完整路径推导

### 例 1 · BP

```
源: datas/商业计划书/【半导体】森国科碳化硅SiC D轮项目商业计划书.pdf
① doc_type  ← source_root=商业计划书                      → BP
② 赛道      ← 【半导体】在 bracket_map                     → 半导体
③ 主体      ← 去【】、去后缀 → 「森国科碳化硅SiC D轮」
              按空白切第一段 → 「森国科碳化硅SiC」
              「D轮」被轮次正则捕获，不进主体
④ 日期      ← 文件名无日期
              封面行「碳化硅（SiC）领先企业 / 森国科D轮商业计划书 / 深圳 / 2022年5月」
              投票通过（该行只含日期与「深圳」）           → 2022-05, date_source=doc_text
⑤ 年份      ← 2022
⑥ 轮次      ← D轮
产物: by_topic/半导体/2022/BP/2022-05_BP_森国科碳化硅SiC_v1.0.md
```

### 例 2 · 行业报告

```
源: datas/行业报告/半导体检测行业报告：集成电路国产化加速，第三方检测发展空间广阔-230722（28页）.pdf
① doc_type  ← source_root=行业报告，名称不含「白皮书/手册」  → REPORT
② 赛道      ← 无【】，keyword_rules 首条命中「半导体」        → 半导体
③ 主体      ← 冒号前 → 「半导体检测行业报告」
④ 日期      ← 文件名 -230722（先剥离「（28页）」防页码误判） → 2023-07-22, date_source=filename
⑤ 年份      ← 2023
产物: by_topic/半导体/2023/REPORT/2023-07-22_REPORT_半导体检测行业报告_v1.0.md
```

## 同主体多文档

`entity_key` 由 `subject_core()` 归一：去地区前缀、去公司形式、取开头连续汉字。

| 文件名主体 | entity_key |
| --- | --- |
| 森国科SiC | 森国科sic |
| 森国科碳化硅SiC | 森国科sic |
| 森国科碳化硅SiCD轮 | 森国科sic |
| 深圳烯钻科技 | 烯钻科技 |
| 中熵科技 / 中熵科技项目 | 中熵科技 |

归并条件是「汉字核心互为前缀且长度 ≥3」。3 字阈值是数据驱动的结果：
中文公司名核心普遍 3–4 字，阈值设 4 会让「森国科」永远无法归并。

人工纠正通道：`datas-md/_index/overrides.yaml`

```yaml
subject_alias:
  森国科: 森国科SiC
```
